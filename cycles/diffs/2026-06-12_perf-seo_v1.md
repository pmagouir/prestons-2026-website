**Budget verdict:** home + /projects are **NEEDS ENGINEER FIXES** (LCP ~370ms over the 2500ms budget; Perf at the 0.90 error floor with zero margin). /personal is within budget. CLS and TBT are excellent everywhere (explicit `width`/`height` on `<Image>` + zero-JS pay off).

**Root-cause evidence:**
- Both the image-LCP route (home) and the text-LCP route (/projects, zero `<img>`, LCP element = a project-card `<p>`) land at the **same ~2.87s**. If the hero image were the home bottleneck, /projects would be faster. It is not → fonts dominate.
- LCP ≈ FCP ≈ Speed Index ≈ 2.9s, **no perf opportunities > 10ms** → nothing is painting until the font critical path resolves.
- Built `dist/index.html` confirms: fonts load via `<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Lora...&Inter...&display=swap">` — a render-blocking, cross-origin, **two-hop** dependency (googleapis CSS → gstatic woff2). `preconnect` to both hosts is present and `display=swap` is set (both good), but the two round-trips under simulated slow-4G are the cost.
- Hero `<Image>` (`Preston1.webp`) ships `loading="eager"`, `decoding="async"`, `width="1280" height="1600"` (good), but **`fetchpriority="auto"`** — Astro's `<Image>` does not emit `fetchpriority="high"` unless told to.

### Ordered Engineer fix list (file · element · change)

**FIX 1 (decisive, clears both routes) — Self-host the fonts; kill the third-party two-hop chain.**
- **File:** `src/layouts/Layout.astro` (head) + `package.json` (add `@fontsource-variable/inter` + `@fontsource/lora`, or use the Astro Fonts API per `core_web_vitals.md §2`).
- **Change:** remove the three `fonts.googleapis.com` / `fonts.gstatic.com` `<link>` lines (lines ~105–107) and the two `preconnect`s (no longer needed once same-origin); import the self-hosted faces in CSS. Subset to the weights actually used (audit the bundle — likely 400/500/600/700 Inter + 400/600/700 Lora; drop any unused weight). Keep `font-display: swap`. Self-hosted woff2 is same-origin, Vercel-edge-cached, `immutable` (per `vercel.md §4`), and removes both network hops from the critical path. **This is the change that moves FCP/LCP on home AND /projects.**
- **Then preload the two above-the-fold faces:** add `<link rel="preload" as="font" type="font/woff2" href="/_astro/<inter-subset>.woff2" crossorigin>` (and the Lora display face) so the browser fetches them in parallel with the HTML parse.

**FIX 2 (home-specific, do alongside FIX 1) — Hero image priority.**
- **File:** `src/components/Hero.astro:45–53`, the `<Image src={prestonImg} .../>`.
- **Change:** add `fetchpriority="high"`. It currently renders `fetchpriority="auto"`. This tells the browser the hero is the LCP candidate and de-prioritizes nothing else above it. (Astro passes `fetchpriority` through as an HTML attribute on `<Image>`.) Helps home's image-LCP; does nothing for /projects (no image), which is why FIX 1 is the one that clears both.

**FIX 3 (optional polish, only if FIX 1+2 leave home short) — drop the hero box height on mobile.**
- **File:** `Hero.astro:43` — the hero portrait container is `h-[400px] … sm:h-[500px] lg:h-[600px]`. On a 360px-wide mobile viewport the rendered image is large; if LCP is still > 2500ms after FIX 1+2, reducing the mobile box (e.g. `h-[320px]`) and tightening `widths`/`sizes` shaves hero decode/paint. Measure after FIX 1+2 first — likely unnecessary.

**Re-verify after fixes:** re-run mobile Lighthouse on `/` and `/projects`; target LCP < 2500ms and Perf ≥ 0.95 (the `core_web_vitals.md §6` stretch). FIX 1 alone should land both well under budget (the font hops are the bulk of the ~2.87s).

**RUM follow-up (not a blocker, standing item):** lab numbers are not production attestation (`core_web_vitals.md §1`, 75th-percentile rule). Confirm Vercel Speed Insights (`speedInsights: { enabled: true }`) is on so real-user LCP/INP/CLS are tracked week-over-week.
